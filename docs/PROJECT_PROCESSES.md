# 프로젝트 프로세스

Projects와 Overview의 등록 진입점은 프로젝트 등록이다. 분류는 콘텐츠, 개발, 운영, 기타이며 프로젝트 안에서 최대 30개의 프로세스를 입력한다. 각 단계의 이름, 완료 여부, 순서를 수정할 수 있다.

미완료 프로세스와 진행 중인 업무는 생성일이나 마감일과 관계없이 매일 Overview의 오늘 할 일과 전체 업무 집계에 포함된다. 완료한 단계는 실제 완료한 한국 날짜의 오늘 완료 업무에 표시된다. 그 외 기존 업무는 오늘 등록 또는 마감 기준을 유지하며 독립 등록 버튼만 제거한다.

프로세스는 기존 tasks 행에 프로젝트와 안정적인 단계 ID를 연결해서 저장한다. 프로젝트를 편집해도 task ID, 메모, 타이머, 작업 일지는 유지된다. 제거한 단계는 보관 처리하고 프로젝트 편집기에서 같은 ID로 복원한다. 보관된 단계의 시간 기록과 당일 완료 기록은 집계에 남는다. 진행 중인 타이머가 있는 단계는 타이머를 종료한 뒤 완료하거나 보관한다.

PERSONAL은 `supabase/personal/020_project_process.sql`, FRENGLE은 `supabase/frengle/004_project_process.sql`을 각각 적용한다. 두 마이그레이션은 기존 업무를 프로세스로 변환하지 않으며 기존 10개 회사 업무를 변경하지 않는다. 모든 RPC와 트리거는 SECURITY INVOKER이고 기존 소유자 및 회사 회원 RLS를 유지한다.

프로젝트 저장은 메타데이터와 모든 단계 변경을 한 트랜잭션으로 처리한다. 이전 편집 화면에서 저장하면 updated_at 충돌을 반환한다. 조회 제한으로 tasks가 일부만 로드된 경우 기존 프로젝트 저장을 막아, 조회하지 못한 단계를 실수로 보관하지 않게 한다.

분류별 시간 집계에서 프로세스는 현재 부모 프로젝트의 분류를 사용한다. 기존 업무는 콘텐츠·영업·디자인·기타 분류를 유지한다. 보관된 프로세스의 누적 시간도 포함한다.
